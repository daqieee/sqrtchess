# RootKnight：根号棋搜索 AI

实现文件为 `my_work.py`，只依赖 Python 3.8+ 标准库及本项目的 `sqrtchess`。
没有修改 `sqrtchess/` 中的文件，没有使用网络、训练数据或第三方库。

## 使用

从项目根目录运行：

```powershell
python -B ai-gpt/my_work.py
```

GUI 中选择“外部程序”，命令行填写：

```text
python -B "ai-gpt/my_work.py"
```

每行一个请求、每行一个响应，标准输出只输出 JSON。支持连续多次请求，不输出启动横幅。

```json
{"request":"ping"}
{"request":"move","fen":"startpos","time_ms":2000}
{"request":"move","fen":"startpos","time_ms":5000,"depth":10,"node_limit":1000000}
```

响应包含 `move`、带大小的 `notation`、`detail` 和 `search`；后者记录完整完成的深度、
分值、节点数、吃子搜索节点数、置换表命中数、耗时和主要变化。
终局返回 `move: null`；错误请求返回 `ok: false`，进程继续处理下一行。
也接受纯文本 FEN。`level` 字段不切换算法，因此兼容现有 GUI 固定发送的 `level: greedy`。

Python 调用：

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path("ai-gpt").resolve()))

from sqrtchess import Game
from my_work import StrongAI, choose, evaluate

game = Game.new()
ai = StrongAI(time_limit=2.0)
move = ai.choose(game)             # 返回引擎的 Move，终局返回 None
print(game.move_dict(move))
print(ai.stats)
game.push(move)

# 也可用 choose(game, time_limit=2.0)，或 MyAI / choose_move 别名。
```

`choose` 不改变传入局面的棋盘、历史、计数和结果。

主要参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `time_ms` / CLI `--time-ms` | 2000 | 协议单步预算，预留 5% 给接口开销 |
| `depth` / CLI `--depth` | 64 | 主搜索最大半回合深度 |
| `node_limit` | 500000 | 主搜索与吃子搜索共用的节点上限 |
| `no_capture_limit` / CLI `--limit` | 100 | 必须与对局设置一致；`null` 或 `off` 关闭 |
| Python `qdepth` | 6 | 主搜索叶子额外的吃子搜索深度 |
| Python `tt_size` | 60000 | 置换表最多条目，0 关闭 |
| Python `use_lmr` | True | 是否减少部分靠后安静着法的搜索深度 |

GUI 请求只含 FEN，无法传递自定义无吃子上限。如果 GUI 改为 50 步，外部命令也应加
`--limit 50`；关闭时加 `--limit off`。FEN 本身不包含这项规则配置。
时间为软实时上限：每个节点检查单调时钟，单个节点和进程调度仍可能造成少量超时。
`time_ms: 0` 返回经排序的合法备用着法；负数、NaN、无穷预算报错。

## 设计与局面评价

根号棋的大小不是传统棋子的固定价值。吃掉大小为 `v` 的棋子，会把双方大小差改变
`2v`，但自身可能变成完全无法移动的大小。此外，无子可动不是通常意义上的被将死：
双方任意一方卡死，都立即比较**子数和大小总和的双重严格优势**。

静态评估先以白方视角计算，最后转换到行棋方视角，100 分表示一个大小单位：

- **物质与子数**：`100 × 大小和差 + 240 × 子数差`。子数具有独立的终局意义。
- **双项优势**：两项同向领先时，额外奖励 `min(300, 100×子数差绝对值, 40×大小差绝对值)`。
- **行动能力**：每枚可动棋子奖励 18 分，每个合法落点 7 分，每个未被敌方几何攻击的落点再加 9 分；
  中心性按离中心的曼哈顿距离计分。没有安全落点再扣 35 分。
- **卡死与拥堵**：当前位置没有任何几何落点，扣 `100 + 5×min(大小,20)`；
  有几何落点、但全部被己方占据，扣 75。卡死棋子仍保留其物质和子数价值，不能当作已经被吃。
- **受攻击风险**：丢子损失按 `240 + 200×大小` 估算；有保护时扣其 1/12，
  无保护时扣其 1/7。不是行棋方的一侧再扣最大威胁的一半。精确交换交给搜索处理。
- **残局接近目标**：总子数不超过 14 时，使用该大小在空棋盘上的最短路，奖励接近可达敌子。
  这样能识别步长、奇偶性和连通分量限制，避免把几何上很近却永远走不到的目标误认为容易吃到。
- **无吃子时钟**：进入上限后半段时强化双项领先的兑现价值；若不能判胜，逐渐削弱静态优势。

权重是基于规则设计的启发式值，没有声称经过大规模训练或最优调参。
攻击图包含被己方占据的落点，用于估计保护；“安全”只是当前棋盘的近似，不能代替向前搜索。
终局完全按真实规则处理：胜负为 `±(1000000 - 根节点距离)`，和棋为 0，优先快胜、延缓必败。
非终局评分限制在 ±250000 内，不能超过胜负分。

## 搜索设计

1. **迭代加深 + Negamax/PVS + Alpha-Beta**。后续着法先用窄窗口试探，超过当前最佳值才完整重搜；
   深度 3 起使用期望窗口，失败后扩大为完整窗口。
2. **置换表**缓存深度、精确值/上下界和最佳着法。键是完整棋盘、行棋方与无吃子计数，
   不把不同计数的局面混用；胜负分按节点距离归一化。每次选步重置，规则配置不会跨请求串用。
3. **走法排序**：置换表着法优先；吃子考虑目标价值、合并后被反吃风险及是否卡死；
   安静着法使用杀手着法、历史启发、逃离威胁和中心改善。
4. **吃子延伸搜索**：正常叶子继续搜索最多 6 层吃子，减少“刚吃完就停止估值”的地平线问题。
   不使用按传统棋子价值删掉亏损吃子的规则，因为变大小与卡死可能反转战术价值。
   无吃子计数即将触发终局时，额外枚举所有合法着法，不允许用“原地不动”的静态分掩盖必和或必败。
5. **保守的后续着法减深**：非根节点、深度至少 4、排序第 7 个以后才可能把安静着法减一层；
   吃子、逃离直接威胁、杀手着法及临近无吃子上限的分支不减。减深结果改善 alpha 时完整深度重搜。
   这是选择性启发式，不保证等价于全宽搜索；`use_lmr=False` 可关闭。
6. **预算控制**：节点和时间任一耗尽立即展开异常返回；每一步内部走子都有 `finally` 撤销。
   只交付最后一个完整完成深度的着法；一层也未完成时仍返回合法备用着法。

没有使用空步剪枝，也不把重复局面擅自判和：本规则可能出现必须行动造成的损失，且没有三次重复和棋规则。
吃子搜索的静态停步仍是有限深度近似，无法消除全部静态估值误差。

为降低 Python 开销，主搜索使用独立棋盘副本、预计算落点和增量物质统计，避免每节点构造引擎棋谱对象。
返回值仍使用引擎的 `Move`，并与根局面的引擎合法着法核对。内部走法与终局判定通过原引擎差分验证。
大于 200 的大小不可能在 11×11 棋盘上移动，直接返回空落点，不做大整数平方根枚举。

## 验证与棋力评价

本仓库可运行的规则回归测试（在项目根目录）：

```powershell

python -B -m unittest discover -s ai-gpt -p test_my_work.py -v
python -B ai-gpt/benchmark.py --time-ms 100 --pairs 2 --output benchmark_new.json
```

> 以下为 AI 原开发阶段的历史验证记录。独立测试、benchmark 脚本及结果 JSON 现已归入本目录；结果和 `engine_hashes.json` 记录的是当时的源码版本，不代表当前合并版本的校验值。

历史测试覆盖：随机合法对局、任意摆放局面、大棋子、双方终局判定、吃子变卡死、
无吃子上限、走子撤销、输入局面不被修改、极短预算、连续协议与错误恢复、战术逃子与毒子。
初始局面的私有走法计数核对到深度 4：22 / 484 / 12342 / 314721。
关闭减深和吃子延伸后，将 PVS 搜索分值与直接使用原引擎的不剪枝三层 Minimax 对照，
同时测试开启/关闭置换表，避免只验证最终着法合法而忽略搜索分值错误。

对局评测使用原引擎判定结果，同一开局交换黑白；第一个开局为标准布局，第二个为固定种子的 6 步随机开局。
对手为项目内置 `greedy`、`capture(depth=4)`、`search2`。逐步着法、起止 FEN、双方用时及搜索深度保存在
`benchmark_results.json`，可据此复核。达到人为步数上限而规则未终局的对局记为 `unfinished`，不会算成胜利或和棋。
这是工程回归样本，不能换算成 Elo，也不能据此证明对任意对手占优。
