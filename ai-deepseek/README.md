# 根号棋 AI - my_work

本目录包含一个可直接运行的根号棋 AI：

```text
ai-deepseek/
├── my_work.py   # 完整 AI（标准库，无第三方依赖）
└── README.md    # 本文档
```

## 1. 运行方式

### 1.1 作为外部 AI（JSON 行协议）

在项目根目录执行：

```bat
python ai-deepseek/my_work.py
```

程序从 stdin 逐行读取请求，向 stdout 输出一行 JSON。支持 `ping` 与 `move`：

```text
{"request":"ping"}
{"request":"move","fen":"startpos","time_ms":1000}
```

响应示例：

```json
{"ok": true, "move": "f2-f3", "notation": "1f2-f3", "depth": 6, "nodes": 77824}
```

在 GUI 的对外程序一栏中可直接填写：

```bat
python ai-deepseek/my_work.py
```

请求中可以使用 `time_ms` 指定思考时间上限；没有提供时默认思考约 1.8 秒。

### 1.2 作为 Python 模块调用

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path("ai-deepseek").resolve()))

from sqrtchess import Game
from my_work import SqrtChessAI, choose_move

game = Game.new()
move = choose_move(game, time_limit=1.0)

# 或复用同一个 AI 对象
ai = SqrtChessAI(time_limit=1.0)
move = ai.choose(game)
print(ai.last_info)
```

## 2. 算法设计

### 2.1 轻量搜索局面

搜索树中不反复构造 `Game` 对象，而是使用一个只含棋盘数组、行棋方、无吃子计数、双方棋子数与大小和、Zobrist 散列的 `_State`。走子与撤销时增量维护这些数据，适合做大量节点搜索。

走法几何按棋子大小预计算：由于规则只看落点，大小为 n 的棋子合法落点只取决于 n、起点和棋盘边界，可缓存为 `size -> 121 个目标格点` 的表，并同时保存目标格点位图。分析局面时可先用 `piece_mask & own_occupied` 一次算出被己方占住的落点数，再用位运算提取敌子目标和空点，从而减少 Python 层循环。

### 2.2 搜索框架

- **迭代加深**：从 1 层开始逐层加深，始终保留最后一次完整迭代的最佳着法。时间耗尽时只丢弃未完成的半轮结果。
- **Negamax + Alpha-Beta**：负极大值搜索，包含 PVS 零窗口试探与失败高重搜。
- **置换表（TT）**：使用 Zobrist 散列，键包含棋盘、行棋方与无吃子计数；保存深度、上下界和最佳着法。
- **着法排序**：TT 最佳着法、吃子、Killer 着法、History 启发、落点几何机动性、吃子后尺寸是否卡死。
- **吃子静态搜索（Quiescence）**：到达主搜索深度后继续搜索强制吃子序列，避免在交换中途停下来造成水平线效应。静态搜索同样检查双方是否已无子可动。

### 2.3 规则终止条件

搜索节点会精确检查：

1. 一方棋子被吃光；
2. 任意一方所有棋子都没有合法落点，立即按规则 7 裁定；
3. 达到无吃子步数上限，按规则 7 裁定；
4. 裁定依据双方棋子数量与大小总和。

终止分值为 `WIN_SCORE - 距离` 形式，因此 AI 会优先选择更快的胜利，并尽量延迟失败。

## 3. 局面评估设计

评估函数从当前行棋方视角出发，考虑下列特征：

| 特征 | 说明 |
| --- | --- |
| 物质差 | 双方棋子大小总和之差。吃子会把被吃子大小并入自己，物质差在交换中变化很大。 |
| 棋子数差 | 规则 7 同时比较棋子数量与大小和；数量优势本身也是重要的裁定资本。 |
| 可动性 | 双方全部合法落点数量之差，衡量主动性和选择空间。 |
| 几何机动性 | 不考虑占用的边界内落点数，反映棋子位置和尺寸的先天活动能力。 |
| 卡死子 | 当前完全没有合法落点的棋子数量。根号棋中 3、6、7、11 等尺寸天然无走法，吃子后变成这些尺寸是核心战术，必须重罚。 |
| 攻击压力 | 当前方能吃到的敌方棋子总大小与最大单子大小；代表先手收益和强制手段。 |
| 受攻威胁 | 对方能吃到己方棋子的对应指标，权重低于己方攻击压力，因为对手要等到下一手。 |
| 无吃子时限靠近度 | 接近 100 步无吃子上限时，若一方在棋子数与大小和上同时领先，则提高其评分，反之降低。 |

此外，评估会特别留意只剩一枚可动子的脆弱局面，并通过搜索中的精确终止判定处理无子可动的即时裁定。

## 4. 正确性与性能验证

- 自定义走法生成与引擎 perft 对齐：深度 1 = 22，深度 2 = 484，深度 3 = 12,342。
- 随机走子后逐节点对比自定义状态与 `sqrtchess.Game` 的棋盘、行棋方、无吃子计数及终止裁定。
- 使用标准引擎接口转换最终着法，返回前再次调用 `Game.is_legal()` 校验。
- 在 1 秒时限的开局搜索中通常可完成 6 层左右并访问约 13 万到 15 万节点；1.8 秒默认时限下通常可完成 7 层，实际深度随局面分支数变化。

## 5. 方案评价

优点：

- 规则实现与搜索分离，终止判断准确，尤其重视根号棋特有的尺寸卡死与无子可动规则；
- 吃子静态搜索显著减少了交换水平线错误；
- 置换表、PVS、Killer/History 与吃子排序让有限时间内能达到较深搜索；
- 纯标准库、无外部依赖，既能作为 GUI 外部 AI，也能直接作为 Python 类使用。

局限与可继续改进方向：

- 评估权重是人工整定的，未做大规模对局自动调参；
- 根号棋的状态空间和吃子不单调性较强，静态搜索仍可能遗漏少量静着战术；
- 未来可加入更精细的受攻格威胁图、开局库、并行根节点搜索或基于自对弈的权重优化。

## 6. 约束说明

本实现只读取并调用 `sqrtchess/` 提供的公开接口，没有修改 `sqrtchess/` 下的任何引擎文件。
